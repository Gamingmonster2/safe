# 🔐 الأمان والدخول — مصروفي

> هذا الملف هو **العقد الملزم** لنظام الحماية. اقرأه كاملاً قبل تعديل `vault.js` أو `store.js`.

## 1. المشكلة التي نحلّها

التطبيق موقع ثابت على GitHub Pages **بلا خادم**. فلا يمكن الاعتماد على «تسجيل دخول» بالمعنى التقليدي:
أي فحص يجري في المتصفح يمكن تجاوزه، وأي «كلمة سر» تُقارَن كنص يمكن قراءتها من الملف.

الحل الصحيح الوحيد بلا خادم: **التشفير**.

```
كلمة السر  →  PBKDF2-SHA256 (310,000 دورة)  →  KEK_pw        (مفتاح كلمة السر)
                                                    │
              verifier = HMAC-SHA256(KEK_pw, 'masrofi-verify')  ← للتحقق السريع
                                                    │
   إن كانت الثنائية مفعّلة:                          ▼
     KEK = HMAC-SHA256(KEK_pw, 'masrofi-kek' ‖ 0x00 ‖ سرّ TOTP)
     (وإلا: KEK = KEK_pw)
                                                    │
                                                    ▼  AES-GCM
                       فكّ تغليف المفتاح الرئيسي MK (32 بايت عشوائي)
                                                    │
                                                    ▼  AES-GCM
                          فكّ تشفير الخزنة (كل بياناتك)
```

### ⚠️ قرار تصميمي مهم: الرمز الزمني لا يدخل في اشتقاق KEK

البديهي أن يكون `KEK = PBKDF2(password + code)`، وهذا **خطأ قاتل** في موقع بلا خادم:
الرمز يتغيّر كل 30 ثانية، فالمفتاح الملفوف يصبح غير قابل للفك بعد انتهاء النافذة ⇒ **قفل دائم** بلا استعادة.

**المطبَّق:** يُدمج **سرّ TOTP الثابت** في اشتقاق KEK، ويُتحقَّق من **الرمز الزمني** بنافذة ±1 فترة
**قبل** فكّ التغليف. النتيجة الأمنية الصحيحة:

| ما يملكه المهاجم | ما يستطيع فعله |
|---|---|
| نسخة `localStorage` فقط | لا شيء — بايتات عشوائية |
| `localStorage` + سرّ TOTP (من الملف) | لا شيء — يحتاج كلمة السر لفكّ تغليف MK |
| `localStorage` + كلمة السر | لا شيء — يحتاج السرّ لفكّ تغليف MK |
| كلمة السر + الجهاز (تطبيق المصادقة) | يفتح ✅ (وهذا هو المقصود) |

## 2. شكل البيانات المخزّنة (localStorage)

| المفتاح | المحتوى | مشفّر؟ |
|---|---|---|
| `masrofi.vault.v1` | الخزنة: `{v, iter, salt, wrap: {iv, ct}, totp: {...}, data: {iv, ct}}` | **نعم** (`data` و`wrap`) |
| `masrofi.vault.meta` | `{ v, username, has2fa, iter, createdAt, updatedAt, hint }` | لا (بيانات وصفية فقط، بلا أسرار) |
| `finapp.v1` | النسخة **القديمة غير المشفّرة** | تُحذف بعد أول تشفير ناجح |

### الخزنة (vault)

```jsonc
{
  "v": 1,
  "kdf": "PBKDF2-SHA256",
  "iter": 310000,
  "salt": "<base64 16B>",              // ملح توليد KEK (عشوائي)
  "verifier": "<base64 32B>",          // HMAC(KEK, "masrofi-verify") — للتحقق السريع من كلمة السر
  "wrap": { "iv": "<12B>", "ct": "<MK مشفّر>" },   // MK = 32B عشوائي
  "totp": {                             // اختياري
    "enabled": true,
    "secret": "<base64 — السرّ نفسه مشفّر AES-GCM تحت KEK_pw>",
    "secretIv": "<12B>",
    "digits": 6,
    "period": 30,
    "algo": "SHA-1",
    "wrappedAt": "..."                 // تاريخ آخر تغيير
  },
  "data": { "iv": "<12B>", "ct": "<حالة التطبيق كاملة JSON مشفّرة>" },
  "updatedAt": "2026-10-06T..."
}
```

**قواعد إلزامية:**
1. `KEK` و`MK` **لا يُكتبان في أي مكان** — لا في `localStorage` ولا في ملف ولا في `console.log`.
   `MK` يبقى في الذاكرة (`CryptoKey` غير قابل للتصدير `extractable:false` بعد الاستخراج).
2. `salt` و`iv` **عشوائيان جديدان** في كل عملية تشفير (`crypto.getRandomValues`).
3. لا `innerHTML`. لا `eval`. لا مكتبات خارجية (Web Crypto فقط — مدعوم في كل المتصفحات الحديثة).
4. كل عمليات Web Crypto **غير متزامنة** — لا تحاول استخدامها بشكل متزامن.
5. عند فشل فك التشفير (كلمة سر خطأ) لا تُمسح الخزنة ولا تُعدّل. رجّع خطأ فقط.

## 3. الواجهة الملزمة — `Fin.Vault` (assets/js/vault.js)

```js
Fin.Vault = {
  // حالة
  isSupported()            // → boolean (هل Web Crypto + TOTP متاحان؟)
  isConfigured()           // → boolean (هل توجد خزنة أصلاً؟ بلا فك تشفير)
  isUnlocked()             // → boolean (هل المفتاح الرئيسي في الذاكرة الآن؟)
  username()               // → string | null
  has2FA()                 // → boolean
  meta()                   // → { username, has2fa, iter, createdAt, updatedAt, hint }
  lock()                   // يمسح المفتاح من الذاكرة فقط (لا يمسح البيانات)

  // الإعداد الأول (عند عدم وجود خزنة)
  setup({ username, password, hint, enable2FA, state })
     // → Promise<{ ok:true, totpSecret?, otpauthURI? } | { ok:false, error }>
     // ينشئ الخزنة ويحفظ `state` الممرَّرة مشفّرة.
     // ⚠️ إلزامي: مرّر `state: Store.snapshotForVault()` وإلا ضاعت بيانات ما قبل الخزنة.
     // إن كان enable2FA صحيحاً يُولّد سرّ TOTP ويرجعه + otpauth:// URI للمستخدم.

  // الدخول
  unlock({ password, code })
     // → Promise<{ ok:true } | { ok:false, error, reason:'bad-password'|'bad-code'|'not-configured'|'locked-out' }>
     // code = رمز TOTP الحالي (6 أرقام) — مطلوب فقط إن كان has2fa.

  // بيانات
  load()                   // → Promise<object|null> (حالة التطبيق المفكوكة؛ null إن كانت مقفلة/فارغة)
  save(state)              // → Promise<{ ok:boolean, error? }> (يشفّر ويكتب؛ يجب أن يكون مؤجَّلاً/debounced من الخارج)
  saveNow(state)           // → Promise مثل save بلا تأجيل

  // إدارة
  changePassword({ currentPassword, code, newPassword })
     // → Promise<{ ok } | { ok:false, error }> (يعيد التغليف بلا إعادة تشفير البيانات كلها)
  disable2FA({ password, code })              // تعطيل بالكامل (من الإعدادات)
  disable2FAWithPassword({ password })        // مخرج طوارئ: تعطيل بكلمة السر وحدها (بلا رمز)
                                              // → {ok:true} | {ok:true, already:true} | {ok:false, reason}
  enable2FA({ password, secret?, digits?, period? })
     // تفعيل لاحقاً من الإعدادات → {ok:true, totpSecret, otpauthURI, digits, period}
     // يشترط أن تكون الخزنة مفتوحة (المستخدم داخل التطبيق)
  exportEncrypted()        // → Promise<{ ok:true, text } | { ok:false, error }> (ملف نسخة مشفّر)
  importEncrypted(text, { password, code })   // → Promise<{ ok:true, state } | { ok:false, error }>
  reset()                  // يمسح الخزنة كلها — يتطلب تأكيداً من الشاشة (ليس هنا)

  // أدوات
  totp: {
    generateSecret()                  // → base32 (بلا حشو) 20 بايت عشوائي
    code(secret, { period, digits, at })  // → '123456' (at = ms أو Date للاختبار)
    verify(secret, code, { window })      // → boolean (يقبل window=±1 فترة)
    otpauthURI({ secret, username, issuer }) // → 'otpauth://totp/...'
    remainingSeconds({ period, at })      // → seconds حتى تجديد الرمز
  },
  utils: { b64, b64d, utf8, random, constantTimeEqual }
}
```

## 4. قواعد التكامل مع المخزن (store.js) — يكتبه اللياد

1. `Store.load()` → إن كانت الخزنة موجودة **ومقفلة**، يرجع `null` ويُظهر `app.js` شاشة القفل.
2. بعد `Vault.unlock` الناجح: `Store.hydrate(await Vault.load())`.
3. كل `Store.save()` يمرّ عبر `Vault.save(state)` (مؤجَّل 400ms) — وإن كانت الخزنة مقفلة لا يُكتب شيء.
4. إن لم تكن هناك خزنة (أول تشغيل) يبقى السلوك القديم: بيانات في `finapp.v1` حتى يُنشئ المستخدم خزنة،
   ثم تُنقل البيانات تلقائياً إلى الخزنة المشفّرة وتُحذف النسخة النصية.
5. `Store.reset()` يمسح البيانات من الخزنة (يبقى الحساب وكلمة السر).

## 5. شاشة القفل (views/lock.js) — يكتبها زميل

شاشتان في ملف واحد:

- **`setup`** (لا توجد خزنة): اسم المستخدم · كلمة السر · تأكيدها · تلميح اختياري · مفتاح «فعّل المصادقة الثنائية».
  - مؤشر قوة كلمة السر: «قصيرة جداً» (< 8) · «مقبولة» (8–11) · «قوية» (12+ مع تنوّع).
  - **لا تُقبل كلمة سر أقل من 8 محارف.**
  - بعد التفعيل: تُعرض شاشة سرّ TOTP: رمز QR (يُرسم SVG محلياً) + السرّ نصاً + 6 أرقام للتحقق.
- **`unlock`** (توجد خزنة): اسم المستخدم (معروض، غير قابل للتعديل) · كلمة السر · خانة الرمز (تظهر فقط إن كان 2FA مفعّلاً).
  - عدّاد تنازلي للرمز (30 ثانية) وزر «جدّد الرمز».
  - بعد 5 محاولات فاشلة: تعطيل مؤقت 30 ثانية (يُحفظ في `sessionStorage` فقط).

## 6. ما لا يفعله هذا النظام (بصراحة)

- **المصادقة الثنائية اختيارية ومُطفأة افتراضياً** (قرار المستخدم: «سنكتفي بكلمة سر قوية، وسأضيف المصادقة لاحقاً»).
  تُفعّل من: الإعدادات ← الأمان ← «فعّل المصادقة الثنائية»، وتُعطّل من نفس المكان.
- **الثنائية ليست عاملاً مستقلاً ضد من يعرف كلمة السر**: `disable2FAWithPassword({password})` تسمح لمالك
  كلمة السر بتعطيل العامل الثاني بلا رمز — وهذا مقصود حتى لا يُقفل المستخدم خارج بياناته أبداً
  (لا خادم ولا استعادة). ما تحميه الثنائية فعلياً: من يملك **الملف/الجهاز** دون كلمة السر أو دون هاتفك.
- **التخطّي في شاشة السرّ يعطّل الثنائية فعلاً** (`lock.js` ينادي `disable2FAWithPassword` بكلمة السر المدخورة).
  لا يجوز أبداً أن يبقى سرّ مسجَّل بلا تأكيد: هذا يُنتج قفلاً دائماً برمز لا يملكه المستخدم.
- لا يمنع أحداً من **استخدام** التطبيق: أي زائر يستطيع التسجيل لنفسه وبياناته منفصلة تماماً.
- لا يحمي من جهاز مصاب ببرمجية خبيثة تسجّل ما تكتبه.
- لا يستعيد كلمة السر إن نسيها أحد — التعافي الوحيد هو **ملف النسخة الاحتياطية المشفّر**.
  لذلك تُذكَّر الشاشة: «صدّر نسخة احتياطية مشفّرة بعد التسجيل».
- البيانات محفوظة في متصفح **هذا الجهاز**. للانتقال لجهاز آخر: نسخة مشفّرة → استيراد من شاشة الدخول.

## 7. اختبارات إلزامية (tests/)

1. إعداد خزنة → قفل → فتح بكلمة سر صحيحة → نفس البيانات.
2. كلمة سر خاطئة → `ok:false, reason:'bad-password'`، والخزنة سليمة، والبيانات لم تُمس.
3. 2FA: رمز صحيح يفتح، ورمز خاطئ يُرفض (`reason:'bad-code'`)، ونافذة ±1 فترة تُقبل.
4. `totp.code` تطابق متجهات معروفة (RFC 6238): السرّ `GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ` عند `59s` → `287082`.
5. `localStorage` بعد التشفير **لا يحتوي** أي رقم من أرقام المستخدم ولا كلمة السر (فحص نصي).
6. `exportEncrypted` → `importEncrypted` بكلمة السر → نفس الأرقام.
7. دورة كاملة: setup → save → lock → unlock → load = نفس الحالة (يمر عبر Web Crypto حقيقي في node 24).
