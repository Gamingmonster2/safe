# tests/ — الاختبار الرسمي لتطبيق «مصروفي»

## التشغيل

من جذر المشروع `C:\vpn\safe`:

```powershell
node tests/check.mjs
```

- **لا مكتبات، لا npm، لا `npm install`** — الملف يستعمل `node:fs` و`node:path` و`node:vm` فقط.
- **لا آثار جانبية**: لا يكتب أي ملف، ولا يستعمل `localStorage` (غير معرّف في node → تُستخدم البذرة `Fin.Store.seed()`)،
  والسكربت قابل للتشغيل مراراً بنفس النتيجة.
- **رمز الخروج**: `0` عند نجاح كل الفحوص، و`1` عند أي فشل (مفيد في CI/النشر).
- المخرج: سطر لكل فحص (`✅`/`❌`) مع **الفعلي** و**المتوقع** عند الفشل، ثم ملخص `PASS n / FAIL m`.

مثال المخرج النهائي:

```
════════════════════════════════════════════════════════════
النتيجة النهائية: PASS 265 / FAIL 2   (من 267 فحصاً)
```

## الأرقام المرجعية الملزمة (اليوم = 2026-10-05)

| البند | القيمة |
|---|---|
| دخل اليوم | 3,400 (سمكرة 1,900 + ميكانيكا 1,500) |
| مصروف اليوم | 302 (120 + 22 + 85 + 60 + 15) |
| صافي اليوم | +3,098 |
| رصيد الشنطة (نقد) | 8,098 = 5,000 افتتاحي + 3,400 − 302 |
| رصيد الادخار | 1,500 |
| إجمالي الحسابات | 9,598 |
| مستحق لي (غير محصَّل) | 5,500 = محل 1,500 + استوديو 2,000 (ربع 2026-Q4) + حجرات 2,000 |
| ديون عليّ (`paid:false` + `debt:true`) | 5,180 = نطاق 180 + رسوم مدرسة 5,000 |
| التزامات قادمة (`planned`) | 1,500 = كتب 950 + زي 450 + بنزين 100 |
| إجمالي الالتزامات | 6,680 |
| إيراد أكتوبر حتى يوم 5 | 3,400 |
| مصروف أكتوبر حتى يوم 5 | 302 |

> **ملاحظة مقصودة (غير محسوبة كفشل):** الرقم «6,400» المتداول في بعض الملاحظات غير مشتق من أي قاعدة:
> بنوده المذكورة نفسها (1,500 + 1,900 + 2,000 + 2,000) = **7,400**، والمحرّك يعطي **5,500** لأن ورشة السمكرة
> 1,900 والورشة الميكانيكية 1,500 **حُصِّلتا اليوم ومربوطتان باستحقاقَيهما** (حالتهما `paid`). المعتمد: **5,500**.
> الاختبار يطبع هذه الملاحظة في قسم «ملاحظات العقد» ولا يعدّها فشلاً.

## كيف تضيف حالة جديدة

1. **حالة معزولة على البذرة**: استدعِ `fresh()` (تساوي `Fin.Store.reset()`) قبل كل حالة حتى لا تتأثر الحالات ببعضها:
   ```js
   {
     let st = fresh();
     const res = Store.recordReceipt('c-2026-10-shop-rent', 700);
     st = Store.state;                       // الحالة بعد التعديل
     near('تحصيل 700 يزيد الرصيد 700', F.cashBalance(st) - 8098, 700);
   }
   ```
2. **أنواع الفحوص المتاحة**:
   - `check(name, cond, actual, expected)` — فحص منطقي عام.
   - `eq(name, actual, expected)` — تساوٍ دقيق (سلاسل/منطقيات/أعداد صحيحة).
   - `near(name, actual, expected, tol = 0.01)` — تساوٍ رقمي بهامش `C.BALANCE_TOLERANCE`.
   - `noThrow(name, fn)` — يتأكد أن الدالة لا ترمي، ويعيد ناتجها للاستخدام:
     ```js
     const s = noThrow('rangeSummary لفترة معكوسة لا يرمي', () => F.rangeSummary(seed, '2026-10-10', '2026-10-01'));
     if (s) eq('فترة معكوسة: صفر معاملات', s.txCount, 0);
     ```
   - `contractNote(text)` — ملاحظة عقد لا تُحسب في `PASS/FAIL` (استعملها لانحراف توثيقي لا لعطل).
3. **القاعدة الذهبية**: لا تُعدّل التوقّع لتُمرّر الفحص. إن اختلف الفعلي عن المتوقع، تحقّق أولاً من القاعدة
   في `ARCHITECTURE.md` والأرقام المرجعية أعلاه؛ إن كان الخطأ في الكود **أبلغ اللياد** ولا تصلحه من هنا
   (`tests/` نطاق كتابة المتحقّق فقط، وملفات المشروع يملكها أصحابها).
4. أضف الحالة في القسم المناسب، وحدّث جدول «ما الذي يغطّيه الاختبار» أعلاه إن أضفت قسماً جديداً.

## ملاحظات معمارية يتحقق منها هذا الملف

- **ترتيب التحميل ملزم**: `constants.js → util.js → finance.js → store.js` (ثم `ui.js` والبقية).
  `store.js` يلتقط `Fin.Finance` وقت التحميل، فإن حُمِّل قبله انهار `Fin.Store.load()` عند أول
  `F.ensureChargeStatus`. القسم 8 يحاكي ترتيب `index.html` الفعلي داخل `vm` ويفشل إن انكسر.
- **`cashFlowForecast`** يعيد كائناً `{asOf, horizon, openingBalance, totalExpected, closingBalance, events, series}`
  بينما `ARCHITECTURE.md §4` يوثّقه كمصفوفة `[{date, expected, cumulative}]`. الاختبار يتعامل مع الشكلين
  ويفحص عناصر `date/expected/cumulative`، ويطبع ملاحظة عقد للتوثيق.
- **البذرة مرتبطة بساعة الجهاز**: `store.js` يستعمل `createdAt` الحقيقي في `ensureCharges`، لذا الأرقام
  المرجعية تُتحقّق على `2026-10-05`. إن تشغّل الاختبار في يوم آخر يظهر فشل واضح في القسم 0 مع شرح السبب.
